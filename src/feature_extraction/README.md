# Feature Extraction Layout

This package is organized around a small plugin architecture.

## Main Entry

- `process_datasets.py`
  - CLI entry for dataset packing and feature extraction.
  - Supports training mode (overlap + optional aug) and inference mode (no overlap).
  - Optional label generation in inference mode via label providers.

## Plugin Registries

- `registry.py`
  - `DatasetHandler` and `RepHandler` protocols.
  - register/get APIs for datasets and reps.

- `feature_plugins.py`
  - Optional user plugin module lists (extra datasets/reps).

## Built-in Datasets

- Dataset modules are auto-discovered from `datasets/*.py`.
- `datasets/slakh.py`
- `datasets/pop909.py`
  - Supports split and non-split layouts, including `versions/original.*`.
- `datasets/giantsteps_key.py`
  - Provides two dataset names:
    - `giantsteps_key`: original GiantSteps layout (`audio/` + labels in `annotations/key` or similar).
    - `giantsteps_key_plus`: GiantSteps+ style layout used previously (`keys_gs+` label folder).
- `datasets/gtzan.py`
  - GTZAN clips under `genres/<genre>/*.wav` (optional `/<split>/genres/...`). Skips `._*` wavs.
  - `track_id` is `<genre>/<stem>` (e.g. `pop/pop.00000`) for Lerch key files.
- `datasets/rwc.py`
  - RWC audio from `AUDIO/*.wav`.
  - Chord labels from `.lab` only (`RWC_Pop_Chords/*.lab`), with id offset mapping `audio 000 -> chord 001`.
- `datasets/fmakv2.py`, `datasets/sae_diagnostic.py`

## Built-in Reps

- Rep modules are auto-discovered from `reps/*.py` (same mechanism as datasets),
  so a new rep only needs one new file there — no edits to `reps/__init__.py`.
- `reps/muq.py` (MuQ), `reps/musicfm.py` (MusicFM).

## Labels (Inference)

- `label_providers.py` is **framework-only**: the `LabelProvider` protocol, the
  registry (`register_label_provider` / `get_label_provider`), and shared
  parsing/encoding helpers (`compute_degree_frames`, `_parse_time_seg_file`,
  `_segs_to_frames`, `_KeyLabelProviderBase`, …).
- Each **concrete** provider lives in its matching dataset module under
  `datasets/` (e.g. `datasets/slakh.py` registers both `SlakhDatasetHandler` and
  `SlakhLabelProvider`). Adding a dataset with labels therefore touches **one file**.
- Current labels: `chord_frame`, `key_frame`, `pitch_roll`, `melody_roll`,
  `tonic_frame`/`forth_frame`/`fifth_frame` (scale degrees).
- Labels are stored **un-transposed** for every augmentation; pitch-shift
  transposition is applied at training time using the per-sample `semitone` field.
- Pop909 `--label-root` can point to either the `POP909` folder or its parent.
- `giantsteps_key` / `giantsteps_key_plus`: key-only providers (`key_frame`); multi-key labels skipped.
- `gtzan`: `--label-root` should be the folder that contains `genres/` (e.g. the cloned
  `gtzan_key` tree). Per-track files: `genres/<genre>/<stem>.lerch.txt` with a single integer
  0–23 (chromatic from **A**: 0–11 major A…G#, 12–23 minor A…G#). ``-1`` = modulation/unknown (track skipped).

## Adding a new dataset (one file)

Create `datasets/<name>.py` that:
- defines a `DatasetHandler` and calls `register_dataset_handler(...)`;
- (optional) defines a `LabelProvider` and calls `register_label_provider(...)`;
- (optional) implements policy hooks read by the core loop via `getattr` with
  safe defaults — `wants_long_silence_filter(mode) -> bool`, `item_unit(mode) -> str`,
  `display_name(mode) -> str`, `track_id_for_path(path, *, mode) -> str`.

No edits to `process_datasets.py`, `datasets/__init__.py`, or `label_providers.py` are needed.

## Utilities

- `audio_utils.py`: audio I/O, silence filter, pitch shift.
- `feature_utils.py`: feature canonicalization.
- `h5_utils.py`: HDF5 append/resize helpers.


## SAE diagnostic synthetic dataset

The dataset generated by `generate_sae_diagnostic_dataset.py` is supported as
`--dataset sae_diagnostic`. Its default audio layout is:

```text
<root>/audio/<family>/<root>_<mode>.wav
```

Each 30-second file is extracted as one sample. Use inference mode so the core
loop disables overlap, augmentation, and silence filtering:

```bash
python -m src.feature_extraction.process_datasets \
  --root /path/to/sae_diagnostic_dataset \
  --dataset sae_diagnostic \
  --split diagnostic \
  --out-h5 /path/to/features/diagnostic_muq_l2.h5 \
  --rep muq_layer \
  --muq-layer 2 \
  --target-sr 16000 \
  --duration 30 \
  --inference \
  --mode mix
```

Equivalently: `python scripts/extract_features.py --purpose eval --dataset sae_diagnostic ...`.

Use the same model id, layer, target sample rate, and representation settings as
were used to produce the features on which the SAE was trained.
